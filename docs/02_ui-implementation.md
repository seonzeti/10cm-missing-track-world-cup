# 02. UI 구현 지침

> 쉽게 말해: 사용자가 보게 될 **화면 4개**를 만드는 단계입니다.  
> 색상·폰트·간격 등 **모든 시각 값은 `DESIGN.md`를 따릅니다.** 이 문서는 "무엇이 어디에 있는지"만 정합니다.

**Take your time.** 작업 전에 `DESIGN.md` 전체를 천천히 읽고, 사용할 색상·폰트 값을 먼저 목록으로 정리하세요.

---

## 1. 구현 범위

- `public/index.html` 한 파일 안에 화면 4개를 `<section>`으로 만들고, 한 번에 하나만 보이게 전환
- `public/css/style.css` 작성
- `public/js/app.js`에서 화면 전환과 버튼 이벤트 연결
- 로딩·오류·빈 상태 표시

이 단계에서 토너먼트 계산은 `tournament.js`(docs/03), 서버 호출은 `api.js`가 담당합니다. `app.js`는 **화면 그리기와 이벤트 연결만** 합니다.

---

## 2. 화면 구성

| 화면 | section id | 언제 보이나 |
|---|---|---|
| 시작 | `screen-start` | 처음 접속, 다시하기 |
| 대결 | `screen-match` | 강 선택 후 ~ 결승 선택 직전 |
| 결과 | `screen-result` | 결승 선택 직후 |
| 누적 순위 | `screen-ranking` | 결과 화면 또는 시작 화면에서 "누적 순위 보기" |

화면 전환은 `hidden` 속성으로 합니다. 보여줄 화면만 `hidden`을 제거하고, 나머지에는 `hidden`을 추가합니다.

```js
function showScreen(id) {
  document.querySelectorAll('section[data-screen]').forEach((el) => {
    el.hidden = el.id !== id;
  });
}
```

## 3. 화면별 요소 (id 고정)

### 3-1. 시작 화면 `screen-start`

| 요소 | id | 내용 |
|---|---|---|
| 제목 | `start-title` | "10CM 팬콘 무대 월드컵" |
| 설명 | `start-desc` | "두 무대 중 더 좋은 무대를 골라 나만의 최애 무대를 뽑아보세요!" |
| 강 선택 버튼 묶음 | `round-options` | 버튼은 docs/03의 `getAvailableRoundSizes()` 결과로 생성. 문구 예: "16강" |
| 시작 버튼 | `btn-start` | "시작하기". 강을 고르기 전에는 `disabled` |
| 순위 버튼 | `btn-go-ranking` | "누적 순위 보기" |

### 3-2. 대결 화면 `screen-match`

| 요소 | id | 내용 |
|---|---|---|
| 진행 표시 | `match-progress` | 형식: `{라운드명} {현재}/{전체}` → 예: "16강 3/8", 결승은 "결승 1/1" |
| 진행 바 | `match-progress-bar` | `<progress>` 태그, value = 지금까지 끝난 매치 수, max = 전체 매치 수 |
| 왼쪽 후보 카드 | `card-left` | `<button>` 안에 이미지 + 곡 제목 + 무대 설명 |
| VS 표시 | `match-vs` | "VS" |
| 오른쪽 후보 카드 | `card-right` | 왼쪽과 동일 구조 |

카드 안 요소 class: `.card-image`(img), `.card-title`, `.card-desc`.  
이미지 `alt` = 곡 제목.

라운드명 규칙: 2명 남음 → "결승", 4명 → "준결승", 그 외 → "{N}강".

### 3-3. 결과 화면 `screen-result`

| 요소 | id | 내용 |
|---|---|---|
| 안내 문구 | `result-label` | "나의 최애 무대" |
| 우승 이미지 | `result-image` | |
| 우승 곡 제목 | `result-title` | |
| 무대 설명 | `result-desc` | |
| AI 한마디 | `result-ai-comment` | 로딩 중: "AI가 한마디 준비 중이에요…" → 응답 도착 시 교체 |
| 저장 상태 | `result-save-status` | "결과를 저장하는 중…" → "결과가 저장되었어요!" / 실패 시 "저장에 실패했어요" + 다시 시도 버튼 `btn-retry-save` |
| 순위 버튼 | `btn-result-ranking` | "누적 순위 보기" |
| 다시하기 | `btn-restart` | "다시하기" |
| 공유 (Should) | `btn-share` | "링크 복사". 클릭 시 현재 주소를 클립보드에 복사 후 "복사되었어요!" 표시 |

### 3-4. 누적 순위 화면 `screen-ranking`

| 요소 | id | 내용 |
|---|---|---|
| 제목 | `ranking-title` | "전체 팬 누적 순위" |
| 총 플레이 수 | `ranking-total` | "지금까지 {N}번의 월드컵이 열렸어요" |
| 순위 목록 | `ranking-list` | `<ol>`. 항목마다 순위, 썸네일, 곡 제목, 우승 횟수, 우승 비율, 승률 |
| 빈 상태 | `ranking-empty` | 플레이 수가 0일 때 "아직 기록이 없어요. 첫 번째 월드컵을 시작해보세요!" |
| 돌아가기 | `btn-ranking-back` | "처음으로" |

순위 항목 표시 예:

```
1  [썸네일]  봄이 좋냐??
   우승 12회 · 우승 비율 24.0% · 승률 71.4%
```

숫자 형식: 비율은 소수점 첫째 자리까지 + "%" (예: 24.0%). 데이터는 docs/04의 `/api/ranking` 응답을 그대로 사용합니다.

내 우승 무대 강조 (Should): 방금 플레이의 우승 후보 항목에 class `is-mine`을 추가합니다.

## 4. 동작 규칙

1. 카드를 누르면 **즉시** 다음 매치를 그립니다. 같은 카드를 빠르게 두 번 눌러도 선택은 1번만 처리합니다 (처리 중 플래그 사용).
2. 다음 매치의 이미지는 미리 불러옵니다(preload). 방법: 현재 매치를 그린 직후 다음에 나올 수 있는 이미지들을 `new Image().src = url`로 로드합니다.
3. 결승 선택 직후 결과 화면으로 이동하고, **저장 요청과 AI 요청을 동시에** 보냅니다. 두 요청은 서로 기다리지 않습니다.
4. 서버 요청 중에는 관련 버튼에 `disabled`와 로딩 문구를 표시합니다.
5. 모든 이미지에 `loading`, `alt`, 그리고 CSS로 고정 비율(`aspect-ratio`)을 지정해 화면이 흔들리지 않게 합니다.

---

## 5. 반응형 기준

- 기본은 **모바일 세로 화면(폭 360px~430px)** 기준으로 만듭니다.
- 모바일: 두 카드를 **위아래**로 배치
- 폭 768px 이상: 두 카드를 **좌우**로 배치
- 실제 색상·폰트·여백 값은 `DESIGN.md`를 따릅니다.

---

## 6. 범위 예시 (few-shot)

**Acceptable**
- DESIGN.md에 정의된 hover/active 효과 적용
- 카드 선택 시 짧은 선택 표시 효과(0.3초 이하) 후 다음 매치로 전환

**Unacceptable → 질문으로 대체**
- 새 화면(예: 후보 상세 페이지) 추가
- DESIGN.md에 없는 색상·폰트 임의 사용
- 외부 UI 라이브러리(Bootstrap 등) 추가

---

## 7. 완료 기준

- [ ] 화면 4개가 3번 항목의 id·문구 그대로 존재
- [ ] 한 번에 화면 1개만 보임
- [ ] 로딩·오류·빈 상태 문구가 모두 구현됨
- [ ] 모바일(375px)과 데스크톱(1280px)에서 레이아웃이 깨지지 않음

## 8. 검증 기준

1. 브라우저 개발자 도구에서 폭 375px로 설정 → 시작부터 결과까지 진행 → 가로 스크롤이 생기지 않는다.
2. 카드를 빠르게 연속 클릭 → 진행 표시 숫자가 한 칸씩만 증가한다.
3. 네트워크를 "Offline"으로 바꾸고 결승 선택 → 결과 화면은 보이고, 저장 상태에 실패 문구와 다시 시도 버튼이 나타난다.
4. 키보드 Tab으로 카드에 이동해 Enter로 선택할 수 있다.
